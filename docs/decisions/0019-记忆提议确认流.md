# 记忆提议-确认流

## 背景

ADR-0018 给记忆备好了双时间轴与溯源数据模型，但写入路径只有手工 CRUD
——"记忆及时更新"缺最后一环：用户在对话里说「我开始服用布洛芬了」，
系统没有任何机制把它变成档案更新。主流方案里 Mem0 用 LLM 自动合并
（ADD/UPDATE/DELETE），但对病历级信息，**模型直写不可接受**：抽取错误的
记忆会污染之后每一次分诊上下文，且静默无声。

## 决策

1. **提议与写入分离**：新增 `memory_proposals` 表（kind/action/payload/
   excerpt/status）。对话结束后 best-effort 抽取候选变更，落 **pending**
   提议；**确认**时才以 `provenance="extracted"` 应用到正式记忆表并写
   审计（`memory_proposal_confirmed`）；**驳回**仅记录决策、不写任何
   记忆。对话原句作为 `excerpt` 附在提议上——确认界面展示依据，溯源
   到"患者当时是这么说的"。
2. **提取器双实现**（延续 mock/real 同构）：mock 模式确定性正则（开始
   服用/停用/把X停用/对X过敏，贪婪捕获 + 语气词/主语剥离 + 连词拆分），
   CI 零依赖可回归；real 模式 LLM 按 rubric 输出 JSON
   （`MEMORY_EXTRACT_PROMPT`），解析失败或字段非法**回落正则**而非报错。
3. **去重与幂等**：同患者同内容（kind/action/名称）的 pending 提议已
   存在时跳过；已处理的提议二次确认/驳回返回 404。
4. **接入点**：chat persist 之后、有 `patient_id` 才触发；best-effort
   （抽取失败静默，不影响对话本身）。
5. **管理面**：前端新增「健康档案」页——待确认提议卡（附原句依据）+
   用药史（当前有效/含历史切换）+ 过敏史 + 随访计划，每条带溯源标签。

## 备选方案

- Mem0 式自动合并直写：放弃——医疗记忆写入必须是人工决定（同
  ADR-0018 保鲜提醒的边界），但**借用了它的合并语义**（add/stop 按
  名称匹配当前有效记录）。
- 复用 HITL 工作台队列：HITL 队列绑定 interrupt 机制与高风险升级语义，
  记忆提议是低风险常态流，混入会稀释工作台的紧急性；独立提议列表 +
  独立审计事件更清晰。前端管理页在「健康档案」就地确认（离数据最近）。
- 向量化情景记忆直入：留待真实向量链路开启后评估（前置条件未满足）。

## 后果

- 「及时更新」闭环：对话 → 抽取提议 → 人工确认 → 双时间轴落库 →
  下次分诊上下文生效，全程溯源 + 审计。
- mock 模式全链路可演示（正则抽取确定性），real 模式换 LLM 决策端点，
  回归口径不变。
- 正则抽取是演示级精度（测试圈定了已知误报边界），real 模式由 LLM
  兜语义精度，失败有正则兜底——两层能力互补而非替代。
- 停药提议按名称匹配当前有效记录，重名药物场景（不同规格同名）可能
  歧义——当前接受，管理界面可后续细化。
