# 患者纵向记忆接入编排链路与意图 LLM 兜底

## 背景

`AgentState.patient_id` 声明后从未赋值、`memory_context` 字段无人写入——患者纵向记忆与图执行完全脱节（首版检查报告 P1-F）。同时意图路由是纯关键词匹配：症状句「头晕，血压偏高」因含"血压"被误判为报告解读（P1-G）。

## 决策

1. **纵向记忆**：新增 `graph/nodes/memory.py:memory_recall_node`，一次查询聚合患者各指标的最新值/单位/较前值变化（`patient_memory.metric_snapshot`，避免逐指标 N+1），格式化为脱敏摘要文本写入 `memory_context`，由分诊提示词消费。`patient_id` 类型修正为 `int | None`，由 `POST /v1/chat/stream` 请求体可选携带。图拓扑：router 之后 triage/medication 先经 `memory_recall`，refuse/report/hitl 分支不查询（不浪费、不给拒答注入噪声）。
2. **意图 LLM 兜底**：real 模式下意图分类交给轻量模型（`tier="fast"`，`INTENT_PROMPT` 约束只输出 triage/report/medication），LLM 失败回落关键词结论；mock 模式保持纯关键词确定性。**急症词命中永远走确定性规则**——安全红线不做模型兜底。

## 备选方案

- 记忆节点放在 scope_check 之前：放弃，拒答/越界请求也要查库，浪费且让噪声进入被拒流程。
- real 模式关键词优先、仅未命中才问 LLM：放弃，修不了"症状句含指标词"这一误路由主场景。

## 后果

- 匿名/评测调用（无 patient_id）行为不变，mock 全链路可测性不回归。
- real 模式每次分诊多一次 fast 模型调用（意图分类），延迟换准确率，属可接受取舍。
