# PHI 脱敏采用逐块惰性 ASGI 中间件

## 背景

安全红线要求 PHI（姓名/身份证/手机/病历号）在"入口中间件"完成脱敏，进入 LLM/RAG 前必须已是脱敏文本，且日志只记脱敏后内容。`api/middleware/phi.py` 需在请求体进入路由前改写。

第一版用 `BaseHTTPMiddleware` + `call_next`：测试发现脱敏"不生效"——`call_next` 内部用**捕获时的原始 `receive`**，路由里 `await request.body()` 读到的是未脱敏原文。第二版改为**原生 ASGI 中间件**直接包裹 `receive`，但实现为"先 `await receive()` 缓冲整段 body 再改写后转发"，在与 TestClient 的流式 `/v1/chat/stream` 端点组合时请求挂起（死锁）。

## 决策

PHI 中间件改为**逐 `http.request` 块惰性脱敏**：不缓冲整段 body，仅对每个收到的消息体做 `mask()` 后透传，保留 `more_body` 语义。这样流式请求无需等待整段 body，兼容 TestClient 与真实 uvicorn。

## 备选方案

- `BaseHTTPMiddleware` + 重新构造 `Request`：因 `call_next` 的 receive 捕获问题放弃。
- 在路由依赖里读 body 再脱敏：放弃，违反"入口中间件统一脱敏"红线，且每个路由都要接。

## 后果

- 正面：入口统一脱敏、对流式端点零侵入、TestClient 下行为正确（8 个单测覆盖）。
- 负面：`mask()` 为逐块正则替换，若 PHI 跨 chunk 边界被拆分则漏脱敏；MVP 风险可接受（请求体通常单块），后续可加边界缓冲。
