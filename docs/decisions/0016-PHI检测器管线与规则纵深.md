# PHI 检测器管线与规则纵深

## 背景

PHI 脱敏此前是 4 个裸正则（safety/phi.py 共 18 行）+ middleware 里复制
的同一组正则做出口检测：两份实现必然漂移；且覆盖面薄（无邮箱/生日/
年龄/住址/社交账号，姓名只认「姓名：」「我叫」两种标签）。

## 决策

1. **单一引擎**：``safety/phi.py`` 重构为检测器管线——``PHIRule(kind,
   pattern, replacement)`` 有序元组；``mask``（入口脱敏）与
   ``detect_kinds``/``detect_phi_leak``（出口泄漏检测）共用同一组规则，
   消除双实现漂移。middleware 只保留 ASGI 包装，实现上收至 safety。
2. **规则纵深**：4 类 → 9 类（新增 email、birth_date、age、address、
   social_account，姓名补「姓+称谓」「老/小+姓」两种无标签启发式，
   就诊号扩展住院号/检查号/影像号等标签）。
3. **保标签替换**：带字段标签的规则只替换值（``病历号[PHI]``），
   信息结构不丢；无标签强标识符整体替换。
4. **两条有意为之的口径**（均有测试锁定）：
   - 姓名标签值只吃 2-4 字，不再吞掉整句（旧实现 ``\S+`` 把后半句
     临床语境一起脱敏）；
   - 年龄仅在显式「年龄」字段时脱敏，自由文本「45岁」保留——年龄是
     分诊的关键临床信息，全量脱敏得不偿失。
5. **模型 NER 留作演进位**：纯规则零依赖、热路径毫秒级、CI 确定性；
   HanLP 等中文 NER 模型需数百 MB 下载且引入推理延迟。``mask`` /
   ``detect_phi_leak`` 接口不变，管线结构支持把 NER 追加为一类
   detector。

## 备选方案

- Microsoft Presidio：英文 NER 为主，中文支持弱，弃。
- HanLP 直接上：能力最强但破坏「mock 全绿零依赖」约束，作为演进位。

## 后果

- 出口检测的 ``detect_phi_leak`` 语义向后兼容（首命中类型或 None），
  新类型可出现在审计明细中。
- 顺带修复旧实现的两个真缺陷（均有旧测试锁定为「错误正确答案」）：
  ``\S+`` 吞掉姓名后的整段文本；``\w+`` 在连字号处截断导致
  「就诊号 OPD-88231」泄漏「-88231」。
- 启发式的误报边界经测试圈定（「小心」「老师」不误伤）。
