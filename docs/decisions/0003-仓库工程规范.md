# 0003 仓库工程规范

## 背景

项目目标含"大厂 Agent 岗位面试作品"，仓库必须体现工程化标准：可复现、可评审、可演示 CI/CD。

## 决策

- **src layout**：`src/care_lifeline/`，测试与实现分离。
- **统一命令入口**：`Makefile`，本地与 CI 同源（杜绝"本地能跑 CI 挂了"）。
- **CI/CD**：`.github/workflows/ci.yml`（push/PR 必跑 lint + type + unit + 覆盖率）、`eval.yml`（评测回归，手动/带 label 触发，报告自动评论）。
- **质量工具**：ruff + mypy + pytest + pre-commit；质控规则模块覆盖率 100% 门禁。
- **协作规范**：根目录 `AGENTS.md`（行为准则 + commit 规范 + 拆分标准 + 安全红线）；`docs/decisions/` ADR 机制。
- **依赖安全**：dependabot 每周巡检；密钥只走环境变量。

## 备选方案

- 平铺目录 + 手动质量检查：搭建快，但不可复现、不可演示工程能力，不选。
- 只用 README 说明规范：无强制力，不选。

## 后果

- 正面：工程化能力可演示、可审计；CI 门禁防回归；AGENTS.md 让 AI 协作稳定可控。
- 负面：初期搭建成本（CI 配置、工具链）略高；工具规则需要维护。
