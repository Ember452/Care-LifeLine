# 质控规则启停持久化（qc_rules 表启用）

## 背景

管理后台 `PUT /v1/admin/rules` 只改 `rules_engine` 进程内字典 `_ENABLED`：重启即丢、多实例不一致。`qc_rules` 表建了但零引用（首版检查报告 P1-D）。

## 决策

1. 规则定义本体保留在 `safety/rules_engine`（代码即规则、可版本化）；`qc_rules` 表只存运维侧启停开关，新增 `enabled` 列。
2. 应用启动时 `sync_qc_rules()` 把当前规则集定义同步进表（首次建行默认启用，已有行只更新元数据、**保留运维改过的状态**），随后 `apply_rule_states()` 用库中状态覆盖进程内开关。
3. `PUT /v1/admin/rules` 双写：内存开关（即时生效）+ 表（持久），并写 `qc_rule_toggled` 审计。

## 备选方案

- 规则定义整体入库：放弃，规则评估逻辑与代码强耦合，入库反而造成两处事实来源。
- 只用内存 + 配置文件：放弃，多实例场景仍不一致。

## 后果

- 规则启停跨重启/实例一致；代价是启动多一次 DB 同步（幂等、可忽略）。
- `safety` 模块覆盖率 100% 门禁覆盖新函数。
