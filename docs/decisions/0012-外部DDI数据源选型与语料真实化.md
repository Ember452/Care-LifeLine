# 外部药物相互作用数据源选型（openFDA）与指南语料真实化

## 背景

工具层此前全部为离线数据：药物相互作用只有 22 条本地 DDI 表（代码注释自认
"生产应替换为 RxNorm + FDA 实时接口"），RAG 指南语料仅 9 个约 600 字节的
手工小文件（合计 ~6KB）。ADR-0011 让 drug_interaction 成为 ReAct 智能体的
首选工具后，"数据是假的"成为演示与面试叙事的最大缺口，需要接入真实外部
数据源且不破坏 mock/CI 的零依赖与确定性。

## 决策

1. **外部 DDI 数据源选 openFDA Drug Label API**（`api.fda.gov/drug/label.json`），
   弃用 RxNav interaction 端点——后者已于 2024-01 被 NLM 下线（实测全量 404，
   官方仅保留 rxcui 名称解析）。选型理由：免费、无 API Key、无需注册；
   检索语义「A 药标签 drug_interactions 一节提及 B 药」即相互作用记录，
   与用药审查场景天然匹配。备选：DDInter（需下载/自托管）、RxCheck（第三方
   创业服务，免费档 100 次/月且需 Key）——均引入额外依赖，弃。
2. **架构**：`tools/ddi_external.py` 提供 `OpenFDAClient`（httpx 异步、
   单请求超时可配置）+ 纯函数解析层（`parse_label_results` /
   `classify_severity` / `merge_interactions`）+ 统一入口
   `fetch_external_interactions`。中文药名经既有别名归一化后查
   中→英映射表（25 种常用药），未收录药品跳过外部查询、不做机器翻译。
   `DrugInteraction` 模型增加 `source` 字段（offline | openfda）以保溯源。
3. **降级语义**：`external_ddi_enabled` 默认 false（本地表为基线，CI/演示
   完全不受影响）；开启后按药品对查询（上限 6 对），单对失败只丢该对，
   整体失败返回空列表——外部数据永远是增强，不是依赖。
   openFDA 404 是「无记录」的正常语义而非错误，与网络失败严格区分。
4. **severity 口径**：openFDA 标签无结构化 severity，按文本启发式
   （contraindicated/serious/severe/life-threatening → major，否则 moderate），
   未知保守取 moderate，与本地表口径兼容。
5. **指南语料真实化**：10 个语料文件全部扩写为分节结构的真实指南要点
   （诊断标准/控制目标/管理要点/就医提示，标注来源指南），合计 ~16KB；
   新增 `drug_interaction_safety.md` 与 DDI 表呼应，使 medication 意图的
   guideline_search 检索有真实依据。语料仍独立于评测集（红线不变）。

## 备选方案

- 继续 RxNav interaction 端点：不可行，官方已下线。
- openFDA 之外自建 DDI 库（DDInter 导入）：能力强但引入数据更新与托管
  负担，作为演进项保留。
- RAG 默认启用本地 sentence-transformers：放弃——模型下载 ~90MB 且 CI
  环境不稳定；`rag_enabled` + `qdrant_url` 开关已存在，启用是配置问题
  而非代码问题（见 .env.example）。

## 后果

- 真实链路可演示：`CARE_EXTERNAL_DDI_ENABLED=true` 下「华法林+阿司匹林」
  实测命中 openFDA 标签记录（~1.7s），与本地表结果按药品对合并去重。
- eval 基线不受影响（默认关闭，指标与 ADR-0011 后一致，P95 25ms）。
- httpx 进入直接依赖（此前仅为传递依赖）。
- 局限：中→英映射表仅覆盖 25 种常用药；severity 为启发式推断而非结构化
  数据；openFDA 免费档限速 240 次/分钟（当前药品对数远低于此）。
- 顺带发现（未在本次修改）：docker-compose.yml 的 api 服务环境变量
  写的是 `JWT_SECRET` 而非 `CARE_JWT_SECRET`，被 pydantic-settings 的
  `CARE_` 前缀过滤，等于未生效——待用户确认后另行修复。
