# 0001 编排与持久化选型

## 背景

需要选定 Agent 编排框架与持久化方案。目标：可上线 MVP + 大厂 Agent 岗位面试作品。要求：多 Agent 协作可控、状态可持久化、面试可讲工程深度。

## 决策

- **编排**：LangGraph（StateGraph / Supervisor + Checkpointer），不自研编排层。
- **持久化**：PostgreSQL（LangGraph PostgresSaver 存会话检查点，另存审计/反馈/规则/评测记录）；Qdrant 存指南向量。

## 备选方案

- 自研编排框架：成本高、轮子重复，不选。
- 纯 LangChain 链式：图执行、分支、持久化能力弱，不选。
- SQLite 持久化：并发与审计能力不足，不选。
- 纯内存（MemorySaver）：demo 级，无会话恢复，仅用于开发/测试，不用于生产。

## 后果

- 正面：Checkpointer 带来会话恢复 / HITL 中断恢复 / 时间旅行回放，是面试叙事点；单一 Postgres 简化运维；审计与评测数据同库可关联。
- 负面：技术栈集中在 LangGraph 生态，学习成本前置；需处理 schema 迁移。
