# 质控循环子图化

## 背景

主图在 ADR-0011 后有 11 个节点，其中 qc↔rewrite 的重写回环占 2 个节点
和 1 条条件边 + 1 条回边：主图 builder 同时感知「业务编排」与「质控内
部收敛机制」两种抽象层次；SSE 层还要为 qc/rewrite 分别准备标签。
文档 §7.5/§8 一直把质控循环描述为一个自洽的"质控 Agent"，代码结构与之
不对应。

## 决策

1. 新增 ``graph/subgraphs/qc_review.py``：qc + rewrite + 重试上限 +
   条件路由编译为独立子图，以 ``qc_review`` 单节点接入主图。
   主图拓扑简化为 ``上游节点 → qc_review → responder``。
2. 子图与主图共享 ``AgentState``：update 经状态合并回写（messages 走
   add_messages reducer，同 id 去重），retry_count / qc_result / draft
   语义不变——回环终止性测试（最坏情况 3 次质控收敛）原样保留。
3. SSE/指标口径变更：agent_step 只发 ``qc_review``（不再有 qc/rewrite
   两个事件）；节点计时以子图为单位。``updates`` 流对子图节点输出的是
   **聚合状态增量**（实测确认），chat.py 消费逻辑无需特判。
4. 编译子图必须经 ``.invoke`` 作为节点函数接入（CompiledStateGraph
   不可直接调用），仍包 ``_timed`` 保持计时口径统一。

## 备选方案

- 保持平铺节点：少一层封装，但主图持续膨胀，子图特性始终为零。
- 子图用独立的窄状态 TypedDict 做输入/输出过滤：更严格但需要手工映射
  十余个字段，共享 AgentState 的方案在实践中无串扰（质检状态字段本就
  只属于质控域），先简后繁。

## 后果

- 主图节点数 11→10，builder 不再含质控路由逻辑；LangGraph subgraph
  特性补齐（tool loop / interrupt / checkpointer / subgraph 全齐）。
- ``_route_after_qc`` / ``_MAX_RETRY`` 迁移至子图模块并改为公开名
  （``route_after_qc`` / ``MAX_RETRY``），旧导入路径随测试同步更新。
- 子图内部各节点的独立耗时不再单独上报（以 qc_review 整体计时），
  如需下钻可在子图内复用 _timed——当前粒度够用。
