# 0004 流式输出与质控冲突的分阶段策略

## 背景

SSE 流式要求低首包延迟，而质控要求在输出前把关，二者存在直接冲突。

## 决策

分阶段演进，不一步到位：

- **M1（现在）**：方案 A —— 全量生成 → QC 双层把关 → 整体流式输出。安全优先，延迟可接受（MVP 阶段 P95 ≤ 15s 目标内）。
- **M2（演进）**：方案 C —— 确定性规则层**前置**（生成前/中实时拦截，可立即中断 SSE 并推送安全提示事件）；LLM 语义评审在流式开始后**并行后验**，超阈值时 SSE 推送纠正事件并标记审计。
- **不采用方案 B**（分块生成 + 分块 QC）：块边界难以保证语义完整，误判率高，复杂度大。

## 备选方案

- 方案 B 分块质控：见上，不选。

## 后果

- 正面：M1 简单可靠；方案 C 是"延迟与安全"的工程平衡点，也是面试叙事点。
- 负面：方案 C 存在"先输出后纠正"的窗口期，需靠规则层前置把窗口压到最小；SSE 协议需支持纠正事件类型。
