# 纵向记忆双时间轴与溯源

## 背景

医疗记忆的核心难题是**事实会过期但历史不能丢**：「在用华法林」半年后
可能早已停用，但「曾用华法林」是重要病史。此前三张记忆表用 `status`
覆盖式表达状态（停药 = 改字段），历史丢失；且每条记忆没有来源（患者
自述/医生录入/会话抽取），管理界面无从建立信任，后续的记忆提议-确认
流（会话抽取写入）也没有落点。

## 决策

1. **双时间轴（SCD-2）**：`patient_medications` / `patient_allergies`
   增加 `valid_from`（默认 now）/ `valid_to`（NULL = 当前有效）。停药/
   过敏失效 = 关闭 `valid_to`，**失效不删行**；查询默认只取当前有效
   切片，`include_history` 连同历史切片返回。
2. **溯源**：三表增加 `provenance`（user 患者自述 | clinician 医生
   录入 | extracted 会话抽取，入库校验枚举）与 `source_session_id`
   （来源会话外键）。`patient_followups` 是任务型记忆（status 表达
   生命周期），不引入双时间轴、只加溯源。
3. **记忆保鲜**：`CARE_MEMORY_REVIEW_DAYS`（默认 180，0 关闭）；
   proactive 扫描超龄未复核的在用药物/过敏记录生成 info 级复核提醒。
   设计边界：**只提醒不改写**——记忆变更必须走人工确认。
4. 已有旧库需重建（dev 为种子数据可重生成；001_init.sql 头部标注
   schema v3）。

## 备选方案

- 用 `is_active` 布尔覆盖：与原 status 同病，历史丢失，弃。
- 全表通用双时间轴（含 metrics）：`patient_metrics` 本身就是时序
  （measured_at 即时间轴），不需要。
- 自动停用过期记忆：违反"记忆变更必须人工确认"的安全边界，以提醒
  代替自动改写。

## 后果

- `structured_summary` / 路由默认切片只出当前有效记忆，失效疗程不进
  分诊上下文；历史在管理界面（include_history）可追溯。
- 为后续「记忆提议-确认流」（会话抽取 → HITL 确认 → 以
  provenance=extracted 落库）准备好了数据模型。
- 保鲜提醒与指标阈值提醒共用 proactive 通道（落库 replace 语义），
  每轮扫描都会重新生成——保鲜提醒天然"直到复核才消失"。
