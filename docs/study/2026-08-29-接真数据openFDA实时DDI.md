# 接真数据：openFDA 实时 DDI 与优雅降级

日期：2026-08-29 ｜ 关联：ADR-0012

## 背景与问题

药物相互作用工具只有 22 条硬编码本地 DDI 表，面试讲"企业级"时这是最明显
的假数据。计划接 RxNorm/RxNav 时实测发现：**NLM 的 Drug Interaction API
（`/REST/interaction/interaction.json`）已于 2024-01 下线**，全量返回 404，
网上教程仍在教这个端点。

## 实现要点

1. **替代端点调研**：候选为 openFDA 标签 API（免费、无 Key、限速 240/min）、
   DDInter（需自托管）、RxCheck（需 Key 的第三方）。选 openFDA：检索语义
   `openfda.generic_name:{A} AND drug_interactions:{B}`——A 药标签的相互
   作用一节提及 B 药即命中，与用药审查场景天然匹配。实测「华法林+阿司匹林」
   命中 75 条标签记录，~1.7s 返回。
2. **降级矩阵**（外部数据是增强不是依赖）：
   - 开关关闭（默认）→ 仅本地表，CI/评测零影响；
   - 单对查询失败 → 只丢该对，其余照常；
   - 整体失败 → 空列表 + 结构化日志（不记药名，避免健康信息入日志）；
   - **openFDA 404 = 无记录的正常语义**，与网络错误严格区分——这是本次
     最重要的语义设计，搞错会把"没有相互作用"当成故障。
3. **纯函数分层**：解析、severity 启发式（标签无结构化字段，按
   contraindicated/serious 等关键词推断，未知保守取 moderate）、按药品对
   合并去重（方向无关、外部优先）全部是可离线测试的纯函数，真实 API
   只占薄薄一层，测试用 httpx 自定义 transport 模拟 404/200/断网。
4. **中文药名处理**：别名归一化（复用既有表）→ 中→英映射（25 种常用药）
   → openFDA 英文检索 → 输出回中文规范名。未收录药品跳过外部查询，
   绝不做机器翻译——查错药比查不到药危险得多。
5. 踩坑：openFDA 不支持 `fields` 参数（返回 400 Invalid parameter）；查询
   串用空格 `AND` 而非 `+`（后者会被拼进搜索词导致 500）。

## 面试预演

**Q：外部 API 挂了怎么办？**
分层降级：单对失败丢该对、整体失败回落本地 DDI 表、默认开关关闭。
药名未收录也直接跳过外部查询。任何情况下用户都能拿到答案，只是新鲜度不同；
`DrugInteraction.source` 字段（offline/openfda）保证结果可溯源。

**Q：severity 为什么是启发式？可信吗？**
openFDA 标签没有结构化 severity，只能从文本推断。这是诚实的工程取舍：
启发式结果作为 LLM 的参考输入，最终回复仍要过质控规则引擎 + 人工复核通道；
生产化路径是接 DDInter 等结构化库做二次校准。

**Q：为什么不用社区教程里的 RxNav？**
实测 404——NLM 2024 年已下线 interaction 端点。选型前先探测真实可用性，
这是接外部数据源的基本功。
