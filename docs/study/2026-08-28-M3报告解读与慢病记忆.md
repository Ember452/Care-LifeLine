# M3 报告解读与慢病记忆：零依赖 RAG + 确定性解析

> 日期：2026-08-28 ｜ 关联功能 / 任务：M3（报告解读 + 慢病管理）

## 背景与问题

医疗报告解读既要"能查指南"（RAG），又要"可复现、不靠 GPU/模型下载就能跑测试"，否则 CI 成本爆炸、评测不可复现。同时报告字段抽取若纯靠 LLM，会引入不确定性与幻觉风险，且无法保证引用溯源。

## 实现要点

- **RAG 零依赖链路**：`EmbeddingPort` 抽象 + `MockEmbedding`（哈希+正弦确定性向量，零参数）；`MemoryVectorStore`（Cosine）；`HybridRetriever` 用 `SimpleBM25`（纯 Python TF）+ 向量，RRF 融合（`score = Σ 1/(k+rank)`，`k=60`）；`Reranker` 抽象 + `MockReranker`（保序）。真实路径 `LocalEmbedding`/`CrossEncoderReranker` 用 `sentence_transformers`，但 `import` 懒加载在方法内，未装依赖时测试零下载。全模块 11 单测。
- **报告解读确定性优先**：`MockReportInterpreter` 按"行 → 冒号分割 → 参考范围正则 → 异常关键词"确定性抽取（参考范围 `(参考范围|参考)?...`，异常词 `偏高/偏低/异常/阳性/升高/降低/超标`）。无 retriever 时回退一条安全引用，保证每次产出结构化 + 引用；`LLMReportInterpreter` 走 provider 解析 JSON，失败回退 Mock，避免单点失效。
- **慢病记忆 + Proactive**：`PatientMetric` 表（纵向时间序列），`patient_memory` 提供 append/trend/latest；`proactive.trigger` 用阈值表（`收缩压>140` 等）对最新值告警，纯函数易测。

## 面试预演

- Q：为什么 RAG 用 Mock 嵌入而不是真模型？ → A：CI 不可下载模型、评测要可复现；通过 `EmbeddingPort`/`Retriever`/`Reranker` 协议把真实实现与测试解耦，真实链路本地 `make index` 触发，接口一致。
- Q：报告字段怎么保证不幻觉？ → A：默认确定性正则抽取，LLM 仅增强；所有结论带指南引用（`citations`），且过 `qc_node` groundedness 校验；越界（诊断/处方）被规则引擎拦。
- Q：混合检索为什么选 RRF 而不是加权？ → A：RRF 无需训练融合权重、对两个召回源排序鲁棒，k=60 是经验稳态值；且 BM25 补语义向量在专有名词/数值上的召回短板。
- 数字：M3 全量 82 单测 `+24`，ruv/mypy 全绿；RAG 11 单测覆盖分块边界、嵌入确定性、RRF 融合、重排保序。
