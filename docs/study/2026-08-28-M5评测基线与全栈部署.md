# M5 评测基线 + CI 回归 + Docker 全栈部署

> 日期：2026-08-28 ｜ 关联功能 / 任务：M5（评测 + 部署 + 打磨）

## 背景与问题

没有量化基线就无法证明"安全可控"；没有 CI 回归门禁，评测集改动能悄悄拉低拒答率/合规率；没有一键部署，演示与交付成本高。更关键：红队/拒答样本若误进 RAG 语料会污染检索上下文（设计文档 §9.3 明令禁止）。

## 实现要点

- **评测基线套件**：`eval/metrics.py` + `eval/suite.py`。`run_suite()` 跑三类数据集（redteam 20 / refusal 15 / report_cases 10，均在 `data/eval/` 且**不进 RAG 语料**），经 Mock 全栈（graph + `MockReportInterpreter`）产出 §9.1 六项指标：拒答率 / 安全率 / 转人工率 / 合规率 / 忠实率(faithfulness) / P95；并渲染 `eval_report.md`。指标用纯函数 `compute_metrics` 便于单测。
- **CI 回归**：`make eval` 调用 `python -m care_lifeline.eval.suite`；`.github/workflows/eval.yml` 在 `workflow_dispatch` 或 PR 打 `eval` label 时跑，上传 `eval_report.md`  artifact 并回评到 PR 评论。
- **全栈部署**：`Dockerfile`（python:3.13-slim + uv）+ `docker-compose.yml`（postgres + api，api 启动自动 `seed_demo` 灌演示用户）+ `db/seed_demo.py` + `.dockerignore`。前端沿用 M3 选定的静态页（非计划里的 React SPA），由 FastAPI 直接托管，故无需 nginx 反代。

## 面试预演

- Q：怎么衡量"安全可控"？ → A：用 §9.1 六项指标建基线；拒答率测红队/越界被拦比例，合规率测回复带免责声明比例，忠实率测带引用比例；`eval_report.md` 可回溯，CI 打 `eval` label 即回归。
- Q：评测样本会不会污染 RAG？ → A：评测集与指南语料物理隔离（`data/eval` 只读、不进检索库），满足 §9.3 防泄漏红线；反馈样本另存 `feedback_cases.json`。
- Q：部署怎么保证鉴权/持久化？ → A：compose 起 Postgres，`CARE_DATABASE_URL` 指向它，JWT 鉴权 + 同步 SQLAlchemy；`seed_demo` 自动建表+演示用户，`make up` 一键起。
- 数字：M5 新增 4 单测（metrics 3 / suite 1），全量 94 passed；评测集 45 用例；`make eval` 稳定产出报告。
- 踩坑：QC 仅在 draft 含越界关键词时拒答，纯离题（"写小说"）当前不拦——基线如实暴露该缺口，是后续意图分类的改进点。
