# 评测双基线与 LLM-as-judge 有据率

日期：2026-08-29 ｜ 关联：ADR-0013

## 背景与问题

评测此前有两个"面试露馅点"：report 用例在评测里硬编码 `MockReportInterpreter`
（real 模式跑分这一路仍是假的）；real 基线会覆盖 mock 基线文件，"评测驱动"
无从对照。设计文档承诺的语义级 faithfulness 与阈值校准（标注集 + PR 选点）
都没落地。

## 实现要点

1. **mock/real 双基线分文件**（`eval_report.md` / `eval_report_real.md`）：
   同一数据集、同一口径、两种栈——两份报告的差值本身就是面试故事
   （"我连评测基线都是双份的，mock 测管线回归，real 测真实指标"）。
2. **有据率 groundedness 用双裁判**，与代码库既有 mock/real 分层同构：
   - mock：确定性代理（真实引用存在性），CI 可回归、零外部依赖；
   - real：LLM-as-judge 按 rubric 逐断言核对，JSON 输出
     `supported_ratio`，解析失败返回 None（用例剔除）而不是记 0——
     **"裁判故障"绝不能伪装成"回复无据"**，这是指标可信度的关键设计。
   - 只对"已回答且带引用"的用例评测，拒答/无引用不进分母（与
     faithfulness 的分母修正同一逻辑）。
3. **阈值校准 harness**（`eval/calibrate.py`）：24 条 pass/block 标注种子集
   → LLMReviewer 打分 → 0.05-0.95 网格扫 PR/F1 → F1 最优、并列取召回
   更高（漏放行的医疗代价 > 多转人工）。纯函数分层（collect/sweep/best）
   全部离线可测，只有打分一步依赖真实 LLM。

## 面试预演

**Q：为什么不直接用 ragas？**
ragas 依赖重、API 版本变动频繁、无法离线进 CI。自研裁判与项目里已有的
QC LLMReviewer 同构（rubric + JSON + 降级解析），口径可解释可单测；输出
语义与 ragas faithfulness 对齐（supported_ratio），后续要换 ragas 只动
裁判实现一层。

**Q：裁判自己打分不准怎么办？**
三层兜底：裁判只对有引用的已回答用例评测；解析失败剔用例而非记 0 分；
mock/real 双报告让"裁判口径 vs 引用存在口径"的差值可见——如果两个口径
严重背离，本身就是评审员 prompt 需要校准的信号。

**Q：24 条标注够吗？**
不够，是显式声明的种子集。扩路径是数据飞轮：workbench 里医生每次审核
（approve/reject/edit + violations）就是天然标注，自动沉淀后校准集可持续
增长——校准 harness 是为"可持续校准"设计的，不是一次性脚本。
