# 记忆提议-确认流：Mem0 的语义 + HITL 的安全通道

日期：2026-08-29 ｜ 关联：ADR-0019

## 背景与问题

「用户说『我开始服用布洛芬了』，系统应该记住」——但医疗记忆不能让
模型直写：抽错一条过敏史，之后每次分诊上下文都被污染，且无人知晓。
Mem0 等主流方案用 LLM 自动合并记忆，对闲聊助手是特性，对医疗是缺陷。

## 实现要点

1. **提议与写入分离**：LLM 只产出 pending 提议（附对话原句 excerpt
   作为依据），确认后才以 `provenance=extracted` 写正式表。人机分工：
   模型负责"发现"，人负责"决定"。excerpt 让确认者一眼看到"患者当时
   是这么说的"——提议不带依据就是逼人盲签。
2. **mock/real 双提取器同构**：mock 用确定性正则（演示/CI 零依赖），
   real 用 LLM rubric 抽取，**LLM 失败回落正则**而不是整链失败。
   正则踩过三个坑（贪婪截断药名、「把X停用了」主语前缀、连词拆分），
   全部来自真机回归——正则简单但每个边界都是真实语句教出来的。
3. **去重与幂等**：同内容 pending 去重防止重复对话刷提议；已处理提议
   二次操作 404。

## 面试预演

**Q：为什么不学 Mem0 让 LLM 自动合并？**
借了它的合并语义（add/stop 匹配当前有效记录、失效不删），但决策权给
人。医疗记忆错一条的成本不是"回答变差"而是"用药建议出错"——这和
质控 Agent 的存在理由同构：能力可以自动化，安全决策必须可确认。
而且我们的架构里记忆写入还带溯源（extracted 标签），确认过的话，
将来出问题能追溯"哪次对话、哪句原句、谁确认的"。

**Q：用户不确认怎么办？**
提议留在 pending 列表，健康档案页一直可见；配套 ADR-0018 的保鲜提醒，
超龄未复核的记忆会通过 proactive 通道催复核。宁可记忆滞后，不可记忆
错误。

**Q：正则抽不准怎么办？**
正则只是 mock/兜底层，real 模式由 LLM 做语义抽取（rubric 限定"只抽
患者明确陈述"）。两层是兜底关系不是替代关系：LLM 挂了正则保底，
保证演示与回归不断；正则误报由"人工确认"这道闸兜住——这就是为什么
先把确认流建好，再谈抽取精度。
