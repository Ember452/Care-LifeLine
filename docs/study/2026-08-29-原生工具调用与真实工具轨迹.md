# 原生 tool-calling：从"表演性工具事件"到真 ReAct 循环

日期：2026-08-29 ｜ 关联：ADR-0011

## 背景与问题

项目自称"多 Agent 平台"，但全仓没有一次原生 tool-calling：路由靠关键词 +
单次 LLM 分类，工具是节点内硬编码直调，SSE 的 `tool_call` 事件是静态字典
映射出来的**假事件**；更糟的是 medication 节点不产 `draft`，QC 对空草稿判
refused——mock 模式下用药咨询实际以拒答文案收尾。面试官一句"Agent 怎么
自己决定调工具"就能戳穿。

## 实现要点

1. **协议先行**：`LLMProvider` 增加 `invoke_with_tools() -> AIMessage`（一轮
   tool-calling），工具用 `ToolSpec`（JSON Schema）描述、schema 挂在
   `CareTool.parameters`——注册表是 schema 单一来源。real 用
   `ChatOpenAI.bind_tools()`（OpenAI function calling），mock 用确定性两轮
   脚本走**同一通路**，CI/评测零外部依赖。
2. **通用 ReAct 节点**（`graph/nodes/tool_agent.py`）：模型自主决定是否调
   工具 → `await tool.run()` → 结果以 `ToolMessage` 回填 → 继续推理，上限
   3 轮。关键容错：未注册工具/执行异常都转成 `ok=False` 的 ToolTrace +
   错误结果消息回填，**让模型改述而不是整轮失败**；轮数耗尽兜底拒答。
   中间消息只留在循环内部不写回图状态。
3. **轨迹贯通**：state 加 `tool_traces: list[ToolTrace]`（含 latency_ms、
   截断 summary），chat.py 从 astream updates 读真实轨迹发 `tool_call`
   事件，删掉静态映射；前端 `SSEToolCall` 契约不变、零改动。
4. **async 节点挂图**：medication 节点变 async 后，builder 里不能再用
   `lambda s: node(s, p)` 包装（同步 lambda 返回 coroutine 不会被 await），
   必须用 `functools.partial(node, provider=p)` 保留 coroutine 语义——这是
   LangGraph 的一个经典坑。

## 面试预演

**Q：为什么不用纯文本 ReAct（Action:/Observation:）协议？**
结构化 `tool_calls` 有协议层解析保障，天然兼容 OpenAI 系端点（Doubao/
DeepSeek），且不用自己写解析容错；文本协议每家模型格式漂移都要适配。

**Q：工具调用失败怎么办？**
两层：单工具失败 → `ok=False` 轨迹 + 错误消息回填，模型可改述或如实告知
（测试覆盖"回填错误后继续作答"）；循环失控 → 3 轮上限 + 兜底拒答文案，
不确定的医学场景宁可拒答也不编造。

**Q：mock 模式跑工具循环有什么意义？**
评测基线必须可回归。mock 走的是与 real 完全相同的图、循环与轨迹通路，
只有"模型决策"这一步是确定性脚本——所以 CI 里 P95 26ms、refusal_rate 1.0
这些数字测的是管线而非模型，切换 real 模式只换决策端点，回归口径不变。

**Q：怎么证明这次改造是真的？**
改造前 mock 模式问"华法林和阿司匹林能一起吃吗"收到的是通用拒答文案
（QC refused，bug）；改造后同样问题 QC passed，回复包含真实 DDI 查询结果，
SSE 里 `tool_call` 事件带真实 args 与 ok 状态，`ToolTrace` 含每跳延迟。
