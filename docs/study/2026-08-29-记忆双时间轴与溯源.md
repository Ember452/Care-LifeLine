# 医疗记忆的"失效不删行"：SCD-2 双时间轴

日期：2026-08-29 ｜ 关联：ADR-0018

## 背景与问题

「在用华法林」半年后可能早已停用。原来的实现是 `status` 字段覆盖式
更新——停药那一刻，"曾用华法林"这段重要病史就从库里消失了。医疗
记忆的正确语义是：**事实会过期，历史不能丢**。

## 实现要点

1. **SCD-2 而非覆盖**：`valid_from` / `valid_to` 双列，停药 = 关闭
   `valid_to`，行永不删除。查询分两个切片：默认"当前有效"
   （`valid_to IS NULL`）进分诊上下文；`include_history` 出全量供
   管理界面追溯。
2. **溯源先行**：`provenance`（user/clinician/extracted 枚举校验）+
   `source_session_id`。这不只是展示字段——它是后续"会话抽取记忆 →
   人工确认 → 落库"流程的数据落点，也是管理界面信任模型的基础
   （医生录入的权重天然高于会话抽取）。
3. **区分两类记忆**：用药/过敏是"关于患者的事实"→ 双时间轴；
   随访是"待办任务"→ status 生命周期。不为了统一而统一。
4. **保鲜 = 提醒而非改写**：超龄记忆生成 info 提醒（复用 proactive
   通道，replace 语义天然"复核前一直提醒"），变更永远走人工。

## 面试预演

**Q：为什么不直接删掉停用的药？**
两个原因：病史价值（"曾用华法林 + 现在出血"是完全不同的临床问题）
和审计一致性（审计日志记了"录入华法林"，业务表却删了行，轨迹对不上）。
SCD-2 让两者都对：当前视图干净、历史可追溯。

**Q：这和 FHIR 什么关系？**
AllergyIntolerance/MedicationRequest 这些 FHIR 资源原生就带
effective period 和 recorded source——我们等于在简化版上重新发明了
这两个字段。医疗信息化几十年的 schema 演进是免费的设计评审。

**Q：过期的记忆为什么不让系统自动停掉？**
医疗记忆变更必须是人工决定。系统连"华法林还在不在吃"都不该猜——
它能做的最好事是准时提醒你来确认。这就是"记忆写入也是质控对象"的
具体体现。
