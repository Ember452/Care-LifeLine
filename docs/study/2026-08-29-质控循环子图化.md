# 质控循环子图化与 LangGraph subgraph 的两个坑

日期：2026-08-29 ｜ 关联：ADR-0015

## 背景与问题

主图 11 个节点里，qc↔rewrite 回环让 builder 同时背两种抽象层次（业务
编排 + 质控收敛机制），SSE 层还要为循环内的每个节点维护标签——质控
"Agent"在文档里是一个整体，在代码里却是两个散节点。

## 实现要点

1. **子图直接复用共享 AgentState**：不另建窄状态、不做字段映射——
   子图输出经父图 reducer 合并回写，messages 走 add_messages 同 id
   去重，行为测试（回环最坏情况 3 次质控收敛）原样通过。先简后繁。
2. **坑一：CompiledStateGraph 不可调用**。把 `subgraph.compile()` 的
   返回值当节点函数直接塞给 `_timed` 包装器，运行时报
   `object is not callable`——必须接 `.invoke` 绑定方法。
3. **坑二：updates 流对子图节点输出的是聚合增量**。实测确认
   `{'review': {最终状态差量}}`，内部节点的逐次 update 不会流出来——
   所以 SSE 的 agent_step 从 qc/rewrite 两条变成 qc_review 一条，
   节点计时也以子图为粒度。这是特性不是缺陷：消费方关心的是
   "质控做了多久"，不是内部循环了几轮。

## 面试预演

**Q：子图化图什么？**
三个收益：主图 builder 回到纯业务编排（qc_review 一个黑盒节点）；
质控收敛保证（重试上限、幂等重写）封装在子图内可独立测试；LangGraph
高级特性凑齐 tool loop / interrupt / checkpointer / subgraph，
每一条都有真实代码和测试。

**Q：子图的 checkpointer 怎么处理？**
子图未传 checkpointer（None）——父图的 AsyncPostgresSaver 负责整个
图的持久化，interrupt（HITL）发生在主图的 hitl 节点，不在子图内，
所以子图不需要内部 checkpoint。
