# 运行时可观测性：给 LangGraph 图装上仪表盘

日期：2026-08-29 ｜ 关联：ADR-0014

## 背景与问题

管理后台号称可观测，实际只有一个端到端 P95。面试官问"线上某次回答慢，
你怎么定位是哪个环节慢的？"——没有每节点延迟，只能抓瞎。

## 实现要点

1. **节点计时最优雅的位置是状态增量**：builder 用 `_timed` 包装器包住全部
   节点（注意 async/sync 要拆成两个工厂函数——mypy 要求条件定义的函数
   变体签名一致；且 `iscoroutinefunction(functools.partial(async_fn))`
   为 True，medication 的协程语义得以保留）。耗时写入 `perf_node_ms`，
   chat.py 从 `astream(stream_mode="updates")` 消费——**依赖方向不破坏**
   （graph 只产出，api 消费），也不用在 LangGraph 内部机制里打洞。
2. **token 计量的诚实性设计**：`TokenUsage.estimated` 字段区分真实计量
   （real 模式读 `usage_metadata`）与字符估算（mock 模式）。估算值让计量
   管线在 CI 可回归，但字段级标注防止"假数字冒充真计量"——这与项目里
   "引用必须带真实 source"是同一个原则：**指标可以是代理，但不能撒谎**。
3. **注册表三参数权衡**：有界样本（1000 条/200 会话防内存无界）、
   threading.Lock 保护、重启清零。换取的是热路径 O(1) 追加、零外部依赖。

## 面试预演

**Q：为什么不上 Langfuse？**
采集点和数据形状都按 Langfuse 的埋点位置设计（节点耗时、provider 用量、
质控结论），接它是加一个 exporter 的事。演示环境先要"零依赖可跑"，
这是 ADR-0007 确立的可切换原则在可观测性上的延续。

**Q：回答慢怎么定位？**
`/admin/metrics` 看每节点 P95：mock 模式下 qc/triage 都在毫秒级；real 模式
如果 qc 节点（LLM 语义评审）P95 明显高于 triage（fast 档小模型），就是
模型分层的依据——这正是我们 fast/strong 双档设计的实证闭环。

**Q：token 成本怎么算？**
done 事件和管理端都有每会话 input/output 累计；estimated 标记区分估算
与计量。接定价表（模型 × 单价）即可出成本，数据结构已就位。
