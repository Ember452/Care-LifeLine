# PHI 脱敏：从 4 个正则到检测器管线

日期：2026-08-29 ｜ 关联：ADR-0016

## 背景与问题

PHI 层是"安全叙事"的门面，实现却只有 18 行：4 个裸正则，而且入口
（middleware 脱敏）和出口（detect_phi_leak 泄漏检测）各维护一份正则
——双实现必然漂移。还藏着两个真 bug。

## 实现要点

1. **单一引擎两入口**：PHIRule(kind, pattern, replacement) 有序列表，
   mask 和 detect_kinds 共用；middleware 只留 ASGI 壳。检测类型
   4 → 9（email/生日/年龄/住址/社交账号 + 姓名启发式）。
2. **两个真 bug 是旧测试锁定的**：`\S+` 把「我叫李四，最近头晕」整段
   吞掉（脱敏顺便毁掉临床语境）；`\w+` 在连字号截断，
   「就诊号 OPD-88231」泄漏「-88231」——半脱敏比不脱敏更隐蔽。
   修这两个 bug 时旧断言就是"错误的正确答案"，更新测试必须写明原因。
3. **保标签替换**：`病历号[PHI]` 而不是把「病历号」一起抹掉——结构化
   字段的字段名不是 PHI，值才是。
4. **临床价值 vs 隐私的取舍**：自由文本「45岁」不脱敏（分诊必需），
   显式「年龄：45」字段脱敏（结构化标识符）。规则写成测试，取舍
   有据可查。
5. **为什么不直接上 HanLP NER**：数百 MB 模型下载 + 推理延迟进热路径，
   破坏 mock 零依赖；PHIRule 管线把 NER 留为可追加的 detector 槽位，
   接口不变。

## 面试预演

**Q：误报怎么办？**
启发式的边界用测试圈定：姓氏表 + 称谓白名单，测试断言「小心」「老师」
不误伤；带标签规则值域限定字符集与长度。漏报靠出口侧 detect_phi_leak
二次兜底 + 泄漏写审计（leak_rate 进管理端指标）。

**Q：为什么入口出口用同一套规则？**
双实现漂移是真实发生过的事故模式。同一 PHIRule 管线保证"入口脱过敏的
形态"与"出口检测的形态"永远一致——出口检测本质上是在模拟
"如果这条文本走了入口，会不会被脱敏"。
