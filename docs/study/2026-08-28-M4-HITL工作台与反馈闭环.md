# M4 HITL 工作台闭环 + 反馈转评测数据集（防泄漏）

> 日期：2026-08-28 ｜ 关联功能 / 任务：M4（HITL 工作台 + 管理后台）

## 背景与问题

高风险对话（胸痛等）必须转人工，但"转人工"如果只是中断回复，医生侧没有可审阅、可决策、可留痕的闭环；且医生修正/驳回的标注若散落，无法沉淀为回归评测集，RAG 语料还可能被污染（PHI/错误结论泄漏进检索上下文）。

## 实现要点

- **审核队列闭环**：新增 `HitlReview` 表（input/draft/qc/violations/patient_context/status/decision/corrected）。chat 流在 `hitl` 分支落库一条 pending 记录（`create_hitl_review`），工作台 `GET /queue` 拉取、`POST /items/{id}/review` 支持 `approve/reject/edit`（edit 强制 `corrected_text`），决议写审计并（edit 时）把修正文本作为 clinician 消息回流会话。
- **运营指标 / 审计 / 规则**：`/v1/admin/metrics` 从 `sessions`/`qc_hits`/`audit_logs` 实时聚合 `refuse_rate/hitl_rate/compliance` 等（无数据时 compliance 取 1.0，`faithfulness/p95` 先占位）；`/v1/admin/audit/sessions/{id}` 返回消息+审计时间线；`/v1/admin/rules` 暴露规则集并支持启停（规则引擎加 `_ENABLED` 注册表，`evaluate_all` 跳过停用项）。
- **反馈防泄漏**：`eval/promote.py` 把已审核项写入独立 `data/eval/feedback_cases.json`（标注 `source: clinician_feedback`），与 RAG 指南语料物理隔离，绝不进入检索上下文——满足"红队/拒答集禁止进 RAG"红线。

## 面试预演

- Q：HITL 怎么和流式对话衔接？ → A：chat SSE 在 `qc.status==hitl` 直接 `event: hitl` + 文案收尾并 `return`，同时同步落库 pending 审核项；医生在工作台决策后状态扭转，会话侧通过 clinician 消息回填，无需重跑图。
- Q：医生反馈怎么防止污染 RAG？ → A：反馈写到单独的 `feedback_cases.json` 评测集，检索只走 `tools/rag` 的指南库，两套存储物理隔离；评测集仅用于离线回归（refusal/红队）。
- Q：规则启停为什么放内存注册表？ → A：MVP 用进程内 `_ENABLED` 字典，零依赖、可单测；生产可换 DB/配置中心，接口（list_rules/set_rule_enabled）不变。
- 数字：M4 新增 8 单测（workbench 3 / admin 3 / promote 2），全量 90 passed；ruff/mypy 干净。
