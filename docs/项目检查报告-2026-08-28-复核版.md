## 3. 当前功能实现详解（复核后口径）

### 3.1 对话与流式：SSE + 伪流式（有明确 ADR 依据）

- 协议：`POST /v1/chat/stream`，SSE 事件扩展到 **10 种**：`meta`（含 scope_verdict）/ `agent_step`（新增，节点级进度可视化）/ `tool_call`（新增）/ `memory`（新增）/ `hitl` / `token` / `qc` / `citation` / `error` / `done`。
- **仍是伪流式**：先 `graph.astream(stream_mode=["updates","values"])` 收集完整图执行，再把 draft 按中文逗号切段 emit。取舍记录在 ADR 0004（先质控后输出 vs 真 token 流的冲突），与首版一致。接真实 LLM 后首字延迟 = 整图耗时。
- 错误处理升级：图异常 → 结构化日志 + `error` 事件；空输入 422；app 级统一异常 handler（app.py:64-109）。

### 3.2 Agent 编排：从 7 节点 DAG → 10 节点带回边循环图

```
START → scope_check → router ─┬→ refuse ──────────────┐（scope 非法，最高优先）
                              ├→ hitl（急症，真 interrupt）┤
                              ├→ report_interpreter    │
                              ├→ triage               │
                              └→ medication ──────────┤
                                                      ▼
                                                     qc ──(blocking/hitl/refused)──→ responder/hitl → END
                                                      │
                                                      └─(warning 且 retry_count<2)→ rewrite → qc  ← 回边循环
```

- **Agent 循环**：qc 判 `warning` 时回边到 `rewrite`（确定性修复：补免责声明 + 引用说明，`retry_count+1` 保证收敛），最多 2 次，`recursion_limit=30` 兜底。这是首版缺失的核心能力。
- **真 HITL**：Postgres 模式下 hitl 节点调用 `langgraph.types.interrupt()` 真暂停图执行，医生在工作台审核后 resume；SQLite（默认）无 checkpointer，走软降级（直接落 hitl_reviews 表 + 固定文案，响应里带 `degraded_no_checkpointer` 标记）。
- **scope_check 前置**：所有请求先过四级范围判定，非法意图在图第一跳就被拒，这是拒答率 100% 的架构基础。
- 旧实测的误路由问题仍在：「头晕+血压偏高」因关键词"血压"进 report 分支（router 仍纯关键词、无 LLM 兜底分类）。

### 3.3 RAG：管线完整，默认 mock、可选 real

- 双路召回（向量 + BM25 单字）→ RRF（k=60）→ top-5 → rerank。
- 后端二选一：`CARE_QDRANT_URL` 配置则 Qdrant（COSINE + 自动建集合），否则内存库。Embedding：mock 模式字符袋哈希（有字符相似度语义，不再是纯随机）；`rag_enabled=True` 时 all-MiniLM-L6-v2（384 维）+ CrossEncoder 重排。
- 语料 9 篇 70 行（糖尿病/高血压/血脂异常/哮喘/COPD/房颤/心衰/缺血性卒中/化验解读），仍是演示级。
- **Tool 化半成品**：`CareTool` 协议 + 注册表已建（4 个工具），但检索仍硬编码在 `report_interpreter` 节点，Agent 尚不能自主决定是否调用工具（mock 模式为确定性节点的设计使然，real 模式的 tool-calling 分支未实现）。

### 3.4 质控：规则 v2（9 条）+ LLM 评审双层

- **第一层规则 v2**：`scope_unsafe / emergency / scope_restricted / scope_out_of_scope`（BLOCKING，消费上游 scope 判定）→ `off_scope`（BLOCKING，draft 兜底黑名单）→ `prescription_leak / diagnosis_leak`（BLOCKING，检测 draft 是否泄蔴剂量用法/诊断措辞——防模型绕过输入侧判定）→ `missing_disclaimer / missing_citation`（WARNING，触发 rewrite 循环修复）。命中 BLOCKING 短路返回。
- **第二层 LLM 评审**：prompt 集中在 `llm/prompts.py`（QC_REVIEW_PROMPT）；real 模式才有语义，mock 模式按 risk_level 给分（维持首版认知）。
- 规则集版本化：`load_ruleset(version)` 支持 v1（冻结）/ v2；**启停开关仍是进程内字典，不落库**（`qc_rules` 表建了但零引用）。
- safety 全模块（rules_engine / scope / llm_reviewer / phi / keywords）覆盖率 **100%**。

### 3.5 工具层与记忆

- DDI 知识库 22 条 + 别名归一化；报告解析支持一行多指标；LLM 解析失败仍静默回退 Mock（无日志）。
- 患者记忆仍只有指标读写（无摘要/画像/embedding 记忆）；`patient_id` 死字段、`memory_context` 无人写入——**纵向记忆尚未接入图执行链路**。

### 3.6 鉴权 / PHI / 审计

- JWT + RBAC（admin/clinician/patient 三角色，role 入 token，403 结构化错误）；登录同时接受 form（OAuth2 兼容）与 JSON（前端契约）；新增 `/register`、`/me`。
- PHI：入口中间件 4 类正则脱敏不变；新增输出侧 `detect_phi_leak()` 检测+审计（不阻断、不改写响应体）。
- 审计：规则变更已写审计、`phi_leak` 有写入方；登录事件仍不写审计；无独立 `audit/` 包（与 AGENTS.md 声明不符）。
- **JWT 默认密钥仍硬编码**（`config.py:33`），无生产环境启动校验。

### 3.7 评测（复核实测，mock 全链路）

```
refusal_rate: 1.0      ← 基线 ≥90% ✅（首版 0.2571）
safety_rate:  0.6      ← 口径缺陷压低，见下
hitl_rate:    0.5067
compliance:   0.8667
faithfulness: 0.1333   ← 口径缺陷压低，见下
p95_ms:       26.79    ← 首版恒 0
```

**两个新口径问题（评测套件的缺陷，不是系统缺陷）**：

1. **safety_rate 0.6 被压低**：30 条 feedback 用例中大量是医生"认可"转人工的急症样本（decision=approve → 期望"正常回答"），但图正确地转了 HITL（blocked）→ 被判为"错误"。`_run_feedback` 的期望映射（suite.py:92）没考虑"approve 的就是转人工回复"这种情况。实际恰当响应比例应为 (35+10+正确 feedback)/75。
2. **faithfulness 0.1333 分母失真**：口径已从"含 `[` 即算"收紧为"引用必须有真实非占位来源"（`citation_has_real_source()`），但分母是全部 75 条——拒答/HITL 文案本来就不带引用。按"回答类用例"算应为 10/10 = 1.0。

**结论：两项低分均为评测脚本口径缺陷，建议修复口径而非系统**（feedback 期望按 `violations` 是否含 emergency 判定；faithfulness 分母排除 refuse/hitl 用例）。

## 6. 后续开发建议（按优先级）

**第一批：锁住成果（半天）**
1. 分批 commit 当前工作区（安全修复 / 图循环 / 前端 / 工程收尾，各一个 commit）——这是当前最大风险项。
2. 修评测口径（P1-B）：feedback 期望按 `violations` 是否含 emergency 判定；faithfulness 分母排除非回答用例。修完 safety_rate/faithfulness 才是真实数字。

**第二批：机制化（1-2 天）**
3. CI 加前端 job（tsc + vitest + build）；pyproject 落 safety `fail_under=100`。
4. 规则启停落库（接上 `qc_rules` 表），登录写审计，删 `CitationRow` 死表或用起来。
5. JWT 生产校验（非 dev secret 拒绝启动）。

**第三批：深水区（按面试叙事价值排序）**
6. **纵向记忆接入图**：chat 入口解析 patient_id → 写入 state → memory 节点读趋势注入 `memory_context`（字段和消费端都预留好了，只差接线）。这是"个性化医疗 Agent"的核心卖点。
7. **真流式**：real 模式下 provider.stream() → 分句缓冲 → 句级质控 → emit（ADR 0004 的方案 C）。
8. **router LLM 兜底分类**（修误路由）：real 模式下 scope_check 顺带产出 intent 分类，替换纯关键词。
9. RAG 检索走 registry tool 化 + 检索质量评测（MRR@5）。
10. SQLite checkpointer（`langgraph-checkpoint-sqlite` 依赖已在）或明确文档化"演示用 SQLite 无会话恢复"。
